# Web → 桌面端迁移契约

> 目标：**保证这个 Web 版能零改造（或近乎零改造）迁移成 Tauri / Electron 桌面端。**
> 本文档定义三层边界与具体的迁移步骤，作为架构约束长期有效。

---

## 0. 结论先行

| 层 | 现状 | 迁移时 | 改动量 |
|---|---|---|---|
| **core/**（git 引擎、分析器、安全模块、存储） | 纯 Node，**不 import 任何 HTTP 相关模块** | 原样复用 | **0** |
| **api.js**（参数解析 → 调 core） | HTTP 路由处理 | 换成 IPC handler | **小**（≈1 个文件） |
| **web/**（前端） | 纯静态，**不依赖任何 Node API** | 原样复用 | **0**（除 `api.js` 一行） |

**唯一的前端改动点**：`web/js/api.js` 里的 `request()`。
把它从 `fetch()` 换成 `window.__TAURI__.invoke()` 或 `electron.ipcRenderer.invoke()`，其余所有视图代码不动。

---

## 1. 三层边界（这是能迁移的根本原因）

```
┌────────────────────────────────────────────────┐
│  web/            纯静态 SPA                     │
│  只通过 transport（web/js/api.js）取数据         │
│  ✗ 不碰 fs  ✗ 不碰 git  ✗ 不 import node 模块    │
└───────────────┬────────────────────────────────┘
                │  transport 可替换
┌───────────────▼────────────────────────────────┐
│  server/api.js   适配器层                       │
│  只做「参数解析 + 调 core」，无业务逻辑           │
└───────────────┬────────────────────────────────┘
                │  普通函数调用（与传输无关）
┌───────────────▼────────────────────────────────┐
│  server/core/*  业务核心                        │
│  git / repo / analyzer / safety / store        │
│  ✗ 不 import http  ✗ 不知道谁在调它             │
└────────────────────────────────────────────────┘
```

**约束（必须长期遵守）**：

1. `server/core/**` 里**禁止**出现 `node:http`、`req`、`res`、`send()` 这类字眼。
2. `web/**` 里**禁止**出现 `require`、`process`、`fs`、`path` 等 Node/Electron API。
3. 所有跨层数据必须是**可 JSON 序列化**的纯对象（这也是前端能直接消费的原因）。
4. `store.js` 对外只暴露函数（`listRepos` / `addLog` …），内部实现（JSON 文件 → SQLite）可换。

---

## 2. 路线 A：Tauri（推荐，体积小、质感最好）

**做法：把现有 Node 服务当作 sidecar 进程拉起。**

```
my-app/
  src-tauri/
    tauri.conf.json        # 配置 sidecar + 静态资源
    src/main.rs            # 启动 sidecar，暴露 IPC 命令
    binaries/gm-server-<triple>.exe   # 由 server/ 打包而来（pkg / node --experimental-sea）
  dist/                    # web/ 的构建产物（其实无需构建，直接拷）
```

- `web/` 静态文件作为 Tauri 的前端资源（`frontendDist`）。
- Rust 侧启动 sidecar，读取它 stdout 里的端口与令牌，通过 IPC 把 `{port, token}` 交给前端。
- 前端 `api.js` 仍走 HTTP（127.0.0.1），**几乎零改动**；或者改成 Tauri IPC 直连，性能更好。

**优点**：二进制 ~10MB，启动快，原生窗口质感最贴合苹果风。
**注意**：sidecar 必须是自包含可执行文件，需要打包 Node 运行时。

---

## 3. 路线 B：Electron（开发最快，改动最小）

**做法：把 core 直接 require 进主进程，`api.js` 变成 IPC。**

```js
// main.js (Electron 主进程)
import { ipcMain } from 'electron';
import { openRepo } from './server/core/repo.js';
import { overview, branches, commits, activity, health } from './server/core/analyzer.js';
import { preflight, switchBranch, undoLast } from './server/core/safety.js';

const handlers = {
  'gm:repos/open':      (_, { path })            => openRepo(path),
  'gm:repos/overview':  (_, { id })              => overview(resolve(id)),
  'gm:repos/branches':  (_, { id })              => branches(resolve(id)),
  'gm:repos/preflight': (_, { id, target })      => preflight(resolve(id), target),
  'gm:repos/switch':    (_, { id, ...payload })  => switchBranch(resolve(id), payload),
  'gm:repos/undo':      (_, { id })              => undoLast(resolve(id)),
  // …
};
for (const [ch, fn] of Object.entries(handlers)) {
  ipcMain.handle(ch, async (_e, args) => {
    try { return { ok: true, data: await fn(null, args) }; }
    catch (err) { return { ok: false, error: { message: err.message, preflight: err.preflight, snapshotRef: err.snapshotRef } }; }
  });
}
```

前端只改一个文件：

```js
// web/js/api.js —— 桌面端版本
const call = (channel, args) => window.gm.invoke(channel, args);   // 由 preload 暴露
async function request(path, { method = 'GET', body } = {}) {
  const res = await call(`${method} ${path}`, body);
  if (!res.ok) { const e = new Error(res.error.message); e.data = res.error; throw e; }
  return res.data;
}
```

> 注意：Electron 下**不要再起 HTTP 服务**，也不需要令牌——IPC 天然只能被本应用的渲染进程调用，安全性由进程边界保证。

**优点**：全是 JS，改一个文件就能跑。
**代价**：体积 ~150MB。

## 4. 迁移时必须补齐的桌面端能力

| 能力 | Web 现状 | 桌面端做法 |
|---|---|---|
| 选择仓库 | 服务端 spawn PowerShell 弹原生对话框（`server/core/dialog.js`） | 换成 Tauri `dialog.open()` / Electron `dialog.showOpenDialog()`，**只改这一个模块** |
| 磁盘扫描 | `server/core/scanner.js`（纯 Node，只读） | **原样复用，0 改动** |
| 窗口 | 浏览器标签 | 无边框窗口 + 自定义标题栏（复用现有设计系统） |
| 令牌鉴权 | 本机随机 token | **可移除**（进程隔离已足够） |
| 缓存 | `data/store.json` | 换 SQLite，`store.js` 接口不变 |
| 自动更新 | — | Tauri updater / electron-updater |
| 托盘 / 开机自启 | — | 按需 |

## 5. 迁移检查清单

- [ ] `grep -r "node:http\|require('http')" server/core/` 结果为空
- [ ] `grep -r "process\.\|require(\|fs\." web/js/` 结果为空
- [ ] `web/js/api.js` 是唯一引用传输方式（`fetch`）的文件
- [ ] `store.js` 未暴露内部实现（JSON 文件路径不泄漏到调用方）
- [ ] 所有 core 返回值为可 JSON 序列化对象（无 Date 对象、无函数、无循环引用）
- [ ] 错误对象统一带 `message` / `preflight` / `snapshotRef` 三个字段，前端错误处理无需修改

---

## 6. 为什么不一开始就做桌面端

- **数据模型需要真实仓库验证**：指标算得对不对，只有接真实仓库才知道，Web 版迭代最快。
- **安全机制需要验证**：Preflight / 快照 / 撤销这套流程，先跑通再包壳，避免把 bug 一起打包。
- **换壳成本被压到最低**：因为 `core/` 与传输无关、`web/` 与宿主无关，换壳是「接线」而非「重写」。

## 7. 实际落地：Electron 桌面版（已实现并打包）

第 2 节列了两条路线。**实际走的是路线 B 的变体**：不是把 `core` require 进主进程、`api.js` 改成 IPC，
而是**把现有 HTTP 服务整体当 sidecar 拉起来，窗口直接加载 `127.0.0.1`**。

这么选的理由，一句话：**改动量最小且失败面最窄**。IPC 方案要把 `server/api.js` 那 500 行
「if-chain 路由 + req/res」重构成传输无关的路由层，那是真重构，会牵动全部既有测试；
sidecar 方案则让 `server/**` 与 `web/**` **一行都不用改**。

### 7.1 运行结构

```
GitManager.exe（Electron 主进程 · desktop/main.js）
   │
   ├─ spawn(process.execPath, ['server/index.js', '--port', '0', '--quiet'])
   │      env: ELECTRON_RUN_AS_NODE=1, GM_DATA_DIR=<用户数据目录>
   │      └─ 启动完成后往 stdout 打一行：GM_READY {"port":…,"token":…,"version":…}
   │
   └─ BrowserWindow 加载 http://127.0.0.1:<port>/
          └─ 页面照常 fetch + x-gm-token，前端零改动
```

| 决定 | 原因 |
|---|---|
| **`ELECTRON_RUN_AS_NODE=1` 让 Electron 二进制以纯 Node 跑 sidecar** | Electron 自带 Node 运行时，**不必再打一份进去**，省约 40MB |
| **加载 `127.0.0.1` 而不是 `file://`** | CSP、相对路径、fetch 全部照常工作；`file://` 下得逐条放宽 CSP 且 `connect-src 'self'` 会拦掉对本地服务的请求 |
| **端口用 `--port 0` 由系统分配** | 用户可能同时开着 Web 版（4599），写死端口会直接起不来。真实端口从 `GM_READY` 读回 |
| **令牌与端口走 stdout，不落盘** | 不落盘就没有「令牌留在磁盘上」这个泄漏面；主进程读到即用 |
| **保留令牌机制** | 换壳不改变威胁模型：它挡不住同源注入脚本，但能挡住**其它本机进程**随意驱动 git 写操作 |
| **`asar: false`** | sidecar 要由 Node 从**磁盘**执行脚本，asar 内的路径不可执行。代价是代码可读——对一个本地工具反而是透明性 |

### 7.2 数据目录策略

| 场景 | 目录 |
|---|---|
| 打包后 | `app.getPath('userData')`（`%APPDATA%\GitManager`） |
| 开发态 `npm run desktop` | 项目里的 `data/`，与 Web 版**共用** |
| 覆盖 | 环境变量 `GM_DATA_DIR` 优先 |

两条硬约束：

1. **打包后绝不写安装目录** —— 安装目录可能只读，且升级覆盖会把用户数据一起抹掉。
2. **`GM_DATA_DIR` 必须被真正尊重** —— 自检脚本靠它做隔离。这正是 `store.js` 曾漏掉、
   导致测试把真实 `data/store.json` 写脏的那个坑，现在有了对应的断言守着。

### 7.3 验证方式：让应用自己跑一遍

桌面端的失败模式几乎都**看不见**：sidecar 起来了但窗口连不上、preload 没注入、令牌没传对、
渲染层 JS 报错导致白屏。静态检查一个都发现不了。

因此 `desktop/main.js` 内置了自检开关（`GM_DESKTOP_SELFTEST=1`）：启动 → 逐项断言 → 退出，
结果打到 stdout **并同时写一份文件**（打包成 GUI 程序后 stdout 不一定接得到父控制台）。
`scripts/check-desktop.mjs` 驱动它，可以用 `--app dist-desktop/win-unpacked` 直接验证**打包产物**。

覆盖的 14 项里，真正有价值的是这几条：

- sidecar 回报了端口、令牌长度合理
- 窗口真的加载了页面、页面读到了正确的版本号与本机令牌
- preload 桥已注入（`window.gmDesktop.isDesktop`）
- 前端渲染出了界面骨架（证明渲染层没抛错）
- 页面经 HTTP 打通本机 API（200）、无令牌请求被拒（403）
- 数据目录策略符合预期，且**隔离目录不等于真实 `data/`**

### 7.4 踩过的坑

**★ `ELECTRON_RUN_AS_NODE` 会把具名导入变成假故障。**
主进程里写 `import { app } from 'electron'` 在**真实 Electron 模式**下是可用的（已实测）。
但只要进程带着 `ELECTRON_RUN_AS_NODE=1` 运行，`electron` 就不再是 Electron 的内建模块，
而是被解析成 `node_modules/electron/index.js` —— **那玩意导出的是二进制路径字符串**。于是：

```
SyntaxError: The requested module 'electron' does not provide an export named 'app'
```

报错在**模块解析期**，一行用户代码都没执行到，信息也完全指不到真正的成因。
（这个坑是被沙箱环境全局设了 `ELECTRON_RUN_AS_NODE` 才撞出来的。）
因此 `desktop/main.js` 统一用**默认导入再解构**，两种模式下都不会炸。

**`app.getPath('userData')` 在开发态与打包态不是同一个目录**：
开发态取 `package.json` 的 `name`（`git-manager`），打包后取 `productName`（`GitManager`）。
所以顶层显式写了 `productName`，两个阶段才落到同一个用户数据目录。

**体积**：Electron 44 的二进制本身就有 235MB，`locales/` 默认带 55 种语言共 49MB。
用 `electronLanguages: ["zh-CN","en-US"]` 裁到 2 种，安装包从 106MB 降到约 93MB。
`LICENSES.chromium.html`（20MB）不能删 —— 那是许可证合规要求。
