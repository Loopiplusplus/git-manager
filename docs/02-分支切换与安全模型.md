# 分支切换与安全模型

> 分支切换是本系统从「只读体检」跨入「可写工具」的第一步，也是**最容易被 AI 搞坏仓库**的地方。
> 本文档定义它的安全边界、执行流程与回滚机制。

---

## 0. 结论先行

| 决策 | 内容 |
|---|---|
| 风险定级 | **L1 可回滚写**；当工作区脏时**自动升级为 L2 破坏性写**处理 |
| 使用的命令 | `git switch`（**不是** `git checkout`） |
| 铁律 | **永不**用 `--force` / `-f` / `reset --hard` 完成切换 |
| 切换前 | **强制跑 Preflight**，检测未提交改动与未跟踪文件冲突 |
| 脏工作区 | **默认先自动快照**（`stash -u` 记录进自有 ref 命名空间），再切 |
| 可撤销 | 每次操作写日志，顶部常驻「撤销上一次切换」 |
| 分支增删 | **新建** L1（只多一个指针）；**删除** L2，且删前把尖端存进 `refs/gm/deleted/*` 作为回收站（见 §5.2） |
| AI 代劳 | 分支切换允许 AI 通过 MCP 调用，但**必须走同一套 Preflight + 日志**，不允许直连 git |

**为什么用 `git switch` 而不是 `git checkout`**：`checkout` 是个"什么都干"的瑞士军刀——它能切换分支、也能覆盖文件路径。AI 只要参数拼错，`git checkout <branch> <path>` 就可能把工作区文件覆盖掉。`switch` 被设计成**只能切分支**，天然不会误分离 HEAD、不会误覆盖路径。这是安全的第一道结构性防线。

## 1. 三级安全模型

| 等级 | 定义 | 示例 | 确认要求 | 快照要求 |
|---|---|---|---|---|
| **L0 只读** | 不改变仓库 | `status` / `log` / `diff` / `ls-tree` | 无 | 无 |
| **L1 可回滚写** | 可被撤销 | `commit` / `branch`(新建) / `stash push` / `switch` | 轻确认 | 建议 |
| **L2 破坏性写** | 可能丢数据 | `branch -D` / `stash drop` / `reset --hard` / `push --force` | 强确认 + 逐条列出受影响对象 | 必须 |
| **L3 禁止** | 永不自动执行 | `clean -fdx`（无 dry-run）/ 自动 `gc --prune=now` | 仅用户手动、且必须在 UI 上明示后果 | — |

> 分支切换平时是 L1；但**只要工作区有未提交内容，就按 L2 走**——因为一次错误的切换真的会让改动消失。

## 2. Preflight 检查清单（切换前必跑）

```bash
# 1. 当前状态（含未跟踪文件），porcelain v2 便于程序解析
git -C <repo> status --porcelain=v2 --branch

# 2. 已跟踪文件的未提交改动
git -C <repo> diff --name-only            # 未暂存
git -C <repo> diff --cached --name-only   # 已暂存

# 3. 目标分支是否存在（本地 / 远端）
git -C <repo> rev-parse --verify --quiet refs/heads/<branch>
git -C <repo> rev-parse --verify --quiet refs/remotes/origin/<branch>

# 4. 未跟踪文件冲突：目标分支里是"已跟踪"、但本地是"未跟踪"的文件
git -C <repo> ls-files --others --exclude-standard      # 本地未跟踪清单
git -C <repo> ls-tree -r --name-only <branch>           # 目标分支跟踪清单
#   两者交集非空 → 切换会被 git 拒绝或覆盖，必须提前预警

# 5. 环境安全检查
git -C <repo> rev-parse --abbrev-ref HEAD                 # 是否 detached HEAD
git -C <repo> rev-parse --git-dir                         # 区分 worktree
git -C <repo> status --porcelain | grep -E '^(UU|AA|DD)'  # 是否有进行中的冲突
```

**判定规则：**

| 检测结果 | 处置 |
|---|---|
| 有未提交改动 | 脏 → 走「快照 / 提交 / 放弃」三选一 |
| 未跟踪文件与目标分支冲突 | **预警并列出文件名**，需用户确认 |
| detached HEAD | **阻止切换**，提示先 `git switch -c` 固化当前提交 |
| rebase / merge 进行中 | **阻止切换**，提示先完成或中止 |
| 分支被其它 worktree 占用 | **阻止**，提示「该分支正被另一个工作树检出」 |

## 3. 安全切换流程（五步）

```
① 选择目标分支  →  ② Preflight 安全检查  →  ③ 脏则自动快照
                                                    ↓
        ⑤ 验证并记日志（可一键回滚）  ←  ④ git switch <branch>（禁用 force）
```

**第 ③ 步：自动快照（默认推荐项）**

用 `git stash create` 生成一个游离提交，再挂到系统自有命名空间，**不污染用户的 stash 列表**：

```bash
sha=$(git -C <repo> stash create "gm-snapshot: before switch to <branch> @ <ts>")
# stash create 不会修改工作区，只生成一个 commit 对象
git -C <repo> update-ref refs/gm/snapshots/<ts> "$sha"
```

> 相比 `git stash push`，`stash create` + `update-ref` 的优点：用户打开 `git stash list` 看不到我们的快照（不干扰他的工作流），但我们有独立 ref 可永久回溯、可按名字单独恢复，也不会被 `stash drop` 误伤。

三选一的另外两项：
- **先提交**：走 L1 commit 流程（用户填 message）。
- **放弃改动**：L2，二次确认 + **展示将被丢弃的 diff 摘要**（绝不静默丢弃）。

**第 ④ 步：切换命令**

```bash
git -C <repo> switch <branch>                            # 切换已有分支
git -C <repo> switch -c <branch>                         # 新建并切换
git -C <repo> switch -c <branch> --track origin/<branch> # 基于远端新建并追踪
```
**引擎层写死：此处不允许出现 `-f` / `--force` / `--discard-changes`。**

**第 ⑤ 步：结果校验**

```bash
git -C <repo> rev-parse --abbrev-ref HEAD   # 必须等于目标分支名
git -C <repo> status --porcelain            # 应为空
```

## 4. 回滚机制

- 每次操作写一条本地日志（SQLite）：`{ id, ts, op, from, to, snapshotRef, result }`
- **撤销上一次切换** =
  ```bash
  git -C <repo> switch <from>
  git -C <repo> stash apply refs/gm/snapshots/<ts>   # 若上一步做过快照
  ```
- 「撤销」本身也记一条日志，形成可追溯链。
- 快照保留策略：默认保留 30 天 / 最多 50 条，超出的按时间清理，清理前提示。

## 5. 硬性禁止清单（写死在 git 引擎层，非 UI 层）

以下命令 / 参数在引擎层**结构性不可达**，UI 不提供入口，AI 通过 MCP 也调不到：

- `checkout`（整条子命令熔断）、`checkout -f` / `--force` / `-f`
- `switch --force` / `--discard-changes`
- `reset` / `clean` / `gc` / `rebase` / `merge`（整条子命令熔断）
- 任何情况下删除当前所在分支、或删掉仓库里唯一的本地分支
- 在 detached HEAD / rebase 进行中 / merge 冲突未解决时执行切换
- `update-ref` 越出 `refs/gm/**`（因此 `update-ref -d refs/heads/main` **写不出来**）

> 这一层必须放在**引擎层**而非 UI 层——UI 可以被绕过，AI 也可以绕过 UI 直接发指令，只有引擎层的白名单命令表才是真正的护城河。

### 5.1 为什么是「窄化白名单」而不是黑名单

黑名单要穷举所有危险写法，永远会漏；本项目的取向是**把参数形态固定死，让危险操作连语法都凑不出来**。

| 子命令 | 允许的形态 | 由此结构性排除 |
|---|---|---|
| `push` | `push [-u\|--set-upstream] origin <单一分支名>` | `--force` `-f` `+refspec` `--mirror` `--all` `--tags` `--delete` `--prune`、通配 refspec |
| `remote` | `remote` / `-v` / `get-url origin` / `add\|set-url origin <url>` | `remove` / `rename` / 非 origin |
| `fetch` | `fetch origin [branch]` | 非 origin、多余参数 |
| `branch` | `branch` ｜ `branch <只读flag…>` ｜ `branch <name> [<起点>]` ｜ `branch -d\|-D <name>` | `-m`（改名）、`-f`、`--force` 拼接 |
| `update-ref` | `update-ref <refs/gm/…> <sha\|HEAD>` ｜ `update-ref -d <refs/gm/…>` | 越出 `refs/gm/**` 的任何操作 |

强制推送之所以不可能，不是因为「被拦住」，而是因为 refspec 正则不允许 `+` `:` `*` —— **没有语法可以写出来**。

> **`branch -D` 不在禁止清单里了**（早期版本曾整条熔断，导致「新建/删除分支」这个能力**在引擎层压根不存在**）。
> 现在它被收窄为 `branch -D <name>` 单一形态，并强制二次确认，见 §5.2。

## 5.2 分支的增与删

### 等级

| 操作 | 等级 | 理由 |
|---|---|---|
| `branch <name> [<起点>]` 新建 | **L1** 可回滚写 | 只是多一个指针，不覆盖任何文件 |
| `branch -d <name>` 删除已合并 | **L2** 破坏性写 | 删掉指向 |
| `branch -D <name>` 强制删除 | **L2** 破坏性写 | 可能丢掉未合并提交 |

### 删除的两道门

1. **`-d` 交给 git 去挡**：分支有未合并提交时 git 会拒绝。
   我们**刻意不自己实现合并判断**去替代它 —— 自己算（`rev-list --count <b> --not HEAD`）会与 git 的 upstream 语义不一致，
   导致把 git 本会放行的分支误拦。所以「有未合并提交」不是 blocker，只是一条要**提醒**的事实。
2. **`-D` 必须 `confirm === name`**，且**校验必须早于任何 git 调用** —— 确认串错了就不该已经动过仓库。

```
删除流程
  ├─ force && confirm !== name  → 立即 400 NO_CONFIRM（此时的仓库一个字节都没动）
  ├─ 只读 Preflight：是否存在 / 是否当前分支 / 是否唯一分支 / 是否被工作树占用
  │                  + 未合并提交数 / 远端同名分支 / 尖端与提交信息
  ├─ 把尖端存进 refs/gm/deleted/<name>-<ts>      ← 关键：否则指针一删就找不到入口
  ├─ git branch -d|-D <name>
  │    └─ 失败 → 清掉刚建的回滚点（分支没变，那个 ref 是多余且会变成「幽灵删除点」）
  └─ 成功 → 记日志，rollbackHint = `git branch <name> <refs/gm/deleted/…>`
```

### 可恢复的删除点

`refs/gm/deleted/*` 就是一张「回收站」。恢复分支 = `git branch <name> <ref>`，不改变任何文件，
所以在界面上它就是一个普通按钮（无需二次确认）。名字里可能含 `-`，用最后一段 `\d{8}T\d{6}` 倒切还原。

### worktree 占用检测的坑

`git worktree list` **会把当前工作树也列出来**。若不排除「本仓库自己」，
一个正被检出的分支就会被误判成「被别的 worktree 占用」，凭空多一个 blocker。
`preflight` / `analyzer` 一开始就做了这个排除，`branchRemovalPrecheck` 最初漏了 —— 已修并补测试。

## 5.3 分支名的合法性校验

**刻意不调 `git check-ref-format`**：那要给引擎再开一个子命令白名单，而且名字以 `-` 开头时它自己也会被当成选项解析，反而更绕。

改用「字符集 + 结构规则」把 git 的 ref 约束表达清楚：

- 字符集：仅 `A-Za-z0-9` 与 `. _ / @ -`；排除空格、`~ ^ : ? * [ \` 及控制字符
- 结构：不能以 `-` / `.` / `/` 开头；不能以 `.` / `/` / `.lock` 结尾；不含 `..` `//` `@{`；不等于 `@`

## 6. UI 交互设计

- **⌘K 快速切换面板**：Spotlight 风格，输入即搜索，`↑↓` 选择，`⏎` 切换，`⌥⏎` 新建分支。
- 每行右侧显示**风险徽章**：
  | 徽章 | 含义 | 颜色 |
  |---|---|---|
  | `当前` | 正在检出的分支 | 苹果蓝 |
  | `领先 n` | 相对远端/主干领先提交数 | 蓝 |
  | `有未提交改动` | 工作区脏 | 橙（警示） |
  | `会覆盖 n 个未跟踪文件` | 切换风险 | 红（危险） |
  | `n 天未动` | stale 分支 | 灰 |
- 脏工作区时，主按钮文案从「切换」变为**「安全切换…」**，点击弹出三选一对话框。
- 危险按钮用橙/红描边 + 二次确认，**确认框里必须列出具体文件名**。
- 顶部常驻「撤销上一次操作」入口；底部常驻操作日志抽屉。

## 7. 边界情况

| 场景 | 处理 |
|---|---|
| worktree | 同一仓库多工作树，目标分支被别的 worktree 检出 → git 拒绝，UI 提示具体路径 |
| submodule / LFS | 切换可能触发 submodule 更新，做成独立开关，默认关闭 |
| 大仓库 | Preflight 的 `ls-tree` 可能慢 → 结果加缓存，按分支名 + commit sha 做 key |
| CRLF / `.gitattributes` | 切换后可能"看起来全部文件都变了" → 需检测并提示，避免用户误以为出问题 |
| 换行符自动转换 | 关闭 `core.autocrlf` 的隐式转换风险，切换不改动用户全局配置 |
| 快照对象被 gc | 自有 ref 会保护对象不被回收；但需在文档里告诉用户"删掉 gm 快照 ref 后旧对象才可能被回收" |

## 8. 与「后续 AI 接入」的关系

MCP 暴露一个受控工具，而非裸命令，例如：

```
git_switch_branch(repo, target, strategy: "snapshot" | "commit" | "abort", commitMessage?)
```

- `strategy` 是**枚举**，AI 无法传入任意 git 参数 → 从接口层就堵死了 `--force`。
- 返回结构化结果：`{ ok, from, to, snapshotRef, warnings[], rollbackHint }`。
- AI 拿到的 `rollbackHint` 是一句可直接执行的「撤销指令」，即使 AI 判断失误，用户也能一键复原。

**核心原则：把安全责任放在接口设计里，而不是放在「提醒 AI 要小心」这种口头约定里。**

## 9. 扫描与目录选择的只读保证

「选择文件夹」与「磁盘扫描」会大规模接触用户磁盘，是实现里风险面最大的部分，因此被设计成**结构上不可能破坏数据**。

### 9.1 系统调用白名单

`server/core/scanner.js` 全文件只使用两个文件系统调用：

- `fs.readdir(dir, { withFileTypes: true })` —— 列目录
- `fs.lstat(path.join(dir, '.git'))` —— 判断 `.git` 是否存在

**没有任何 write / mkdir / rename / unlink / chmod**。缓存只写进本项目自己的 `data/` 目录，绝不写入被扫描目录。

### 9.2 判定「是否仓库」的方式

只看 `.git` **是否存在**（目录或文件都算，兼容 worktree / submodule），**不读取、不解析 `.git` 内容**。

### 9.3 防越界三道闸

| 闸门 | 实现 |
|---|---|
| 不跟随链接 | `if (e.isSymbolicLink()) continue`，杜绝死循环与跳出根目录 |
| 路径包含性校验 | 每个子目录入队前校验 `resolved(child) ⊂ resolved(root)`；Windows 下大小写不敏感比较 |

> **★ 这个校验踩过一个坑（已修，见 §9.7）**：不能写成 `path.resolve(root) + path.sep`。
> 当 root 是**盘根**（`E:\`）时，`path.resolve` 返回的字符串**已经自带结尾分隔符**，
> 再拼一次 `path.sep` 就变成 `E:\\`（两个反斜杠），于是任何子路径都不可能 `startsWith` 它 ——
> 队列永远为空，扫盘根一个仓库都找不到。
> 正确做法是两边都先规整成「不带重复结尾分隔符」的形态（`withTrailingSep()`）再比较。
> **通用规则**：凡「父路径 + 分隔符」做前缀比较，都必须先规整，别假设 `path.resolve` 不带结尾分隔符。
| 深度上限 | `depth < maxDepth`，硬上限 10 |

### 9.4 防失控三重预算

- 深度 ≤ 10（默认 5）
- 目录数 ≤ 400,000
- 时间 ≤ 5 分钟（默认 3 分钟）

任一超限即优雅停止并把状态回传给前端（`timeout` / `limit`）。扫描全程 `setImmediate` 让出事件循环，保证**随时可取消**且不长时间占满磁盘 I/O。

### 9.5 默认跳过清单

系统区域：`Windows`、`Program Files*`、`ProgramData`、`AppData`、`$RECYCLE.BIN`、`System Volume Information`、`Recovery`、`PerfLogs`、`$Windows.~BT/WS`、`MSOCache`、`OneDriveTemp`
重量级缓存：`node_modules`、`.git`、`.svn`、`.hg`、`__pycache__`、`.cache`、`.npm`、`.pnpm-store`、`.yarn`、`.gradle`、`.m2`、`.cargo`、`.rustup`、`.conda`、`site-packages`、`.next`、`.nuxt`、`.turbo`
类 Unix：`Library`、`.Trash`、`snap`、`proc`、`sys`、`dev`、`run`、`lost+found`

> 跳过清单只影响**效率**，不影响正确性 —— 即使漏掉某个目录，也只是少找到一个仓库，绝不会误删或误改。

### 9.6 原生文件夹选择器

浏览器出于安全拿不到真实绝对路径（File System Access API 只返回句柄），所以选择器由**本地服务端**调用 Windows 原生对话框实现：

- 服务端 `spawn powershell.exe -NoProfile -STA` + WinForms `FolderBrowserDialog`
- 用「不可见但置顶」的宿主窗体作为 owner，确保对话框弹在最前
- 路径经 **Base64(UTF-8)** 回传，彻底规避控制台编码压坏中文路径
- 180 秒超时自动取消，不留孤儿进程
- **只回传路径字符串**，不读任何文件内容

> 桌面端迁移时，这个模块（`server/core/dialog.js`）被原生 API 整体替换，`api.js` 契约不变。

### 9.7 实测验证

在临时夹具目录（含 3 个仓库、1 个 `node_modules` 内仓库、1 个非仓库目录）上验证：

- 扫描前后**文件大小、修改时间、目录结构完全一致**，未新增任何文件
- `node_modules` 内的仓库被正确跳过
- 深层仓库（depth 4）被正确发现
- 不存在的路径 / 传入文件 → 400 拒绝

**盘根回归（真实盘，非夹具）**：`E:\` 修复前 **0** 个仓库 → 修复后 **12** 个（depth 2–3），
扫 4912 个目录 / 2.9s / 0 错误；`C:\` 也能扫到。
这条边界现在进了 `scripts/check-branch.mjs` 的第 2 组（纯函数断言 `pathIsInside` / `withTrailingSep`）——
真实扫盘太慢不适合放进回归，所以把判定函数导出后单独覆盖，避免这个 bug 再溜一次。
